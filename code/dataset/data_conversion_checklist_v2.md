# 학습 데이터 변환 점검표

작성 2026-09-30 · 적용 대상: Isaac 기록(재생 · 정책 롤아웃)으로 OpenVLA · OFT · GR00T 학습 데이터를 만들 때

학습을 망치는 데이터 결함은 대부분 **학습 중 오류를 내지 않는다.** 학습은 끝까지 돌고 손실도 줄어드는데 평가에서 로봇이 엉뚱하게 움직인다. 아래는 이 프로젝트에서 실제로 겪은 결함을 막는 순서다. 하나라도 확인하지 않았으면 학습 서버에 올리지 않는다.

## 1. 변환 전 — 데이터 출처의 시간 규약부터

같은 번호 k 가 **스텝의 어느 순간**을 가리키는지 출처마다 다르다. 코드의 실행 순서로 확인한다.

| 출처 | 화면 k | 상태 k | 액션 k | 학습 짝 |
|---|---|---|---|---|
| MuJoCo LIBERO 원본 (기준) | 명령 k 직전 | 명령 k 직전 | k | (화면 k, 액션 k) |
| Isaac 정책 롤아웃 (평가 기록) | 명령 k 직전 | 명령 k 실행 후 | k | (화면 k, 액션 k), 상태는 k−1 을 씀 |
| **Isaac 재생 (`libero_eef_pose`)** | 시연 k−1 번째 자세 | 시연 k 번째 자세 | 시연 k | **(화면 k+1, 액션 k)**, 마지막 스텝 제외 |

브리지 루프: ① `world.step` → `get_images()` (화면 k, 녹화 · 정책 입력) → ② 명령 실행 (재생은 `replay_eef_positions[k]` 로 이동) → ③ `record_policy_step` (상태 k).

> 09-30 에 이 표 없이 변환해 재생 데이터 화면이 한 스텝 늦은 학습셋(v4)을 만들었다. 변환기 v3 도 같은 가정이었다.

## 2. 변환 중 — 변환기가 막아야 하는 것 (`build_finetune_dataset_v4b.py`, 재생 데이터는 `IMAGE_OFFSET = 1`)

| 검사 | 실패 사례 | 기준 |
|---|---|---|
| 집게 규약 | 09-15 · 09-23 집게 반전으로 여닫기 반복 | 액션 집게 값이 −1 / +1 이고 원본과 같음 |
| 이미지 방향 | 09-23 이미지 반전 | 같은 시연 LIBERO 첫 화면과 네 방향 비교, 「그대로」 가 가장 닮음 |
| 정지 프레임 | 09-15 no-op 27 % 로 성공률 0 % | no-op 비율 < 1 % |
| 길이 · 끝 | 성공 조기 종료로 영상이 짧음 | 실행된 스텝까지만, 영상 수와 차이 0–2 |
| 크롭 | 학습 · 평가 시야 불일치 | 증강(0.9) 을 쓰면 학습 크롭 = 평가 크롭 ÷ 0.9 (평가 0.35 → 학습 0.389) |
| 액션 분포 | 09-25 정규화 통계 오류 | q01 · q99 를 원본과 비교해 기록 |

## 3. 변환 후 — 시간 정렬 검증 (`verify_dataset_v4c.py`)

| 검사 | 기준 |
|---|---|
| V6 상태 번호 | 시작점을 맞춘 뒤 Isaac 상태 k 와 MuJoCo 상태 k+L 의 거리가 L = 0 에서 가장 작음 |
| V5b 화면 ↔ 자기 상태 | 화면 변화–손끝 속도 곡선의 봉우리가 원본 LIBERO 에서 같은 계산의 봉우리와 같음 |
| V5 화면 ↔ 액션 | 화면 변화–액션 크기 곡선의 봉우리가 원본 LIBERO 와 같음 |
| V7 집게 시점 | 닫기 명령 뒤 0–3 스텝 안에 손가락이 닫히기 시작 |

- 시연 액션은 부드러워서 곡선이 평평하다. **「지연 0 인가」 도 「봉우리 칸이 같은가」 도 아니라, 포물선으로 찾은 봉우리 위치가 원본과 0.5 스텝 안인가**로 판정한다 (`verify_dataset_v4c.py`).
- 화면 ↔ 액션(V5) 비교에는 재생 모드의 자세 추종 지연(상태가 MuJoCo 를 약 0.4 스텝 늦게 따라감)이 섞인다. V6 에서 구한 추종 지연만큼 빼고 본다.
- 09-30 실측: v4 는 V5b 차이 −1.29 · V5 −1.94 (밀림), v4b 는 V5b −0.22 · V5 −0.60 · 추종 −0.44 (통과).
- 가짜 데이터로 검사기를 시험하면 곡선이 뾰족해 잘 잡히지만, 실제 데이터에서는 판별력이 약하다. 의심이 들면 **코드의 실행 순서**로 원인을 확정한다.
- 새로 만든 시험은 결론 전에 시험 자체가 의도대로 동작했는지 본다 (09-30 「움직이기 시작한 스텝」 비교는 문턱값이 검색 시작점에서 넘어가 무효).

## 4. 학습 서버 — 등록 · 통계

- 데이터셋 이름이 LIBERO 와 같은 변환(집게를 [0, 1] 로 자르고 뒤집기)에 등록돼 있는지 (`prismatic/vla/datasets/rlds/oxe/configs.py` · `transforms.py`).
- RLDS 빌더의 이미지 크기 · 키 이름이 npz 와 같은지. 빌드 후 첫 에피소드를 읽어 npz 와 같은지 대조.
- 학습 후 체크포인트의 `dataset_statistics.json` q01 · q99 가 변환 보고서의 값과 같은지.
- 평가 서버의 역정규화 키가 새 데이터셋 이름인지 (`libero_spatial` 이 아님).

## 5. 여러 출처를 섞을 때

- 출처별로 1 의 표에 맞춰 따로 정렬한 뒤 합친다.
- 출처 표지(`source`)를 파일에 남긴다. 결과가 나쁘면 출처별로 빼 보며 원인을 찾는다.
